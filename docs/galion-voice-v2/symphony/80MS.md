Europe/Zagreb. 2026-11-06. Symphony section. Index: [README.md](README.md).

The spelling is **Galion**. The product is Galion Voice.

The 80 ms frame is the existing lock. It is not a latency this page measured. `LOCKS.toml` `[clock]` has `frame_ms = 80`, `frame_hz = 12.5`, and `configurable = false`. There is no second clock. This page does not edit `LOCKS.toml`.

The path that runs on that lock is Rust. `FRAME_MS` in `crates/galion-heartbeat` is 80. `SAMPLE_RATE` is 24000. `FRAME_SAMPLES` is 1920 mono samples. `scripts/run-live-demo.sh` builds `galion-live-demo` and takes one `Heartbeat::step` per frame. `scripts/run-v1-screen.sh` builds the Rust console on the same clock. The clock and the crate are [HEARTBEAT.md](HEARTBEAT.md).

A sector that rides this clock finishes inside the frame. A late frame pauses. The next frame does not catch up. Heavy speech, recognition, and the clone child run off the tick. The tick decides. It does not wait on a model.

## Python is a cross-check

Python does not advance the frame.

| Tool | What it checks |
|---|---|
| `galion-demo/galion_demo.py` | Canned policy port. Its heartbeat comment points at this lock. The samples that run are `galion-live-demo`. |
| `scripts/symphony/eval.py` | Reads `LOCKS.toml`. It does not write `frame_ms`. |
| `docs/galion-voice-v2/symphony/scripts/ttfa_check.py` | Reads the lock and the Rust constant. A stub has no product latency. |
| `scripts/symphony/check-g-latency.sh` | Uses `python3` to confirm `frame_ms` is 80 and that `FRAME_MS` matches. The step it times is `cargo test -p galion-heartbeat`. |

A Python interpreter inside `Heartbeat::step` fails the bar.

## Run

```bash
LIVE_REALTIME=1 scripts/run-live-demo.sh
cargo test --offline -p galion-heartbeat
```

`--realtime` sleeps one frame so the wall clock and the lock match. The heartbeat tests cover a late frame: it is delivered paused, and the next frame does not catch up. This page did not run these commands here.

## Gate

**PASS** when a run on the machine being scored records the lock's `frame_ms` of 80, and any streaming-sector time in that run was measured on that machine.

**FAIL** when a live sector blocks the tick, when a late frame glitches ahead to make up time, or when Python advances the frame.

**BLOCKED** when the realtime demo has not been run on the machine being scored. **BLOCKED** for every CPU or latency figure this page would otherwise print.
