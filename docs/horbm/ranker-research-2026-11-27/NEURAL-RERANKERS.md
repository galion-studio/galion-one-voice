# (41) Ranker research — neural rerankers

Desk note, 2026-11-27. Research only. No model was downloaded and nothing was timed on a Galion machine. A number below is someone else's measurement, with the source named. Where this note has no measurement, it says I don't know.

The job is part (41): several sourced cards are already in hand, and the ranker picks one card or abstains. A miss speaks exactly `I don't know.` The ranker does not write a new sentence. Empathy already rewrites the lookup and does not speak the feeling (`horbm/crates/horbm/src/lib.rs`). Persona match is a filter, not a second index (`docs/horbm/foundations/F2-retrieval-audit.md` on the unmerged R3 note). This lane only scores retrieval match.

What runs today is not a boosted tree. `KnowledgeCards::lookup` keeps a card only when every content token of the ask is in the card. The smallest haystack wins. Two haystacks of the same length are a miss, not a guess (`horbm/crates/horbm/src/cards.rs`). The retrieval thread returns at most four hits (`MEMORY_HIT_CAP`, `docs/horbm/PLAN-brain.md`). The pack those loaders read is 1,506 cards (`docs/horbm/foundations/phase4-brain-deep-dive.md`). Rust is pinned at 1.85 (`horbm/Cargo.toml`). `LOCKS.toml` forbids in-tree `ort` and treats `candle` as a dev oracle. This note does not change that file.

The XiaoIce card (Zhou et al., Computational Linguistics, 2020) is a boosted tree over cohesion, coherence, empathy, and retrieval match, plus a threshold. That tree needs graded labels and hand-built features. HORBM has little or no labelled ranking data. A neural reranker does not supply the empathy or coherence features. It supplies a retrieval-match score, and only some of them supply a score you can abstain on.

## Options

Each line is the year, where it lives, the licence, and one sentence.

1. **BERT cross-encoder, 2019.** [Nogueira and Cho](https://arxiv.org/abs/1901.04085). Weight licence: I don't know from the pages read here. One BERT pass over the query joined to the passage, then a relevance probability from the `[CLS]` vector.
2. **MS MARCO MiniLM and TinyBERT cross-encoders, cards posted 2021–2022.** [MiniLM-L6 card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2), [sentence-transformers table](https://github.com/huggingface/sentence-transformers/blob/main/docs/cross_encoder/pretrained_models.md). Apache-2.0 for TinyBERT-L2, MiniLM-L6, and MiniLM-L12 ([Lasagna licence table](https://dolev31.github.io/lasagna/docs/model-licenses/), a third-party reading of the Hub cards). A distilled BERT that scores one query–passage pair as a single logit.
3. **monoT5, 2020.** [Nogueira, Jiang, Pradeep, and Lin](https://arxiv.org/abs/2003.06713). The paper is the method. The `castorini/monot5-base-msmarco-10k` card states no licence ([same table](https://dolev31.github.io/lasagna/docs/model-licenses/)). T5 reads `Query: q Document: d Relevant:` and the score is the softmax probability of the token `true` against `false`.
4. **RankT5, 2022.** [Zhuang et al.](https://arxiv.org/abs/2210.10634). The paper is CC-BY-4.0 on arXiv. A T5 ranker trained with pairwise or listwise losses so the output is an order, not a yes/no probability.
5. **ColBERT, 2020, and ColBERTv2, 2022.** [Khattab and Zaharia](https://arxiv.org/abs/2004.12832), [Santhanam et al.](https://aclanthology.org/2022.naacl-main.272.pdf). Code repo is MIT ([stanford-futuredata/ColBERT](https://github.com/stanford-futuredata/ColBERT/)). The `colbert-ir/colbertv2.0` weight licence: I don't know from the card itself; the Lasagna table lists MIT. Encode the query and the card separately, then sum, over query tokens, the max cosine against card tokens (MaxSim). Card vectors can be stored ahead of the turn. PLAID is the later search engine for that index ([Santhanam et al., CIKM 2022](https://arxiv.org/html/2205.09707)).
6. **answerai-colbert-small-v1, 2024.** [Model card](https://huggingface.co/answerdotai/answerai-colbert-small-v1), [blog](https://www.answer.ai/posts/2024-08-13-small-but-mighty-colbert.html). Apache-2.0. A 33.4M late-interaction model, same MaxSim idea as ColBERT, built to run on CPU.
7. **SPLADE, 2021, and the 2022 efficiency models.** [Formal, Piwowarski, and Clinchant](https://arxiv.org/abs/2107.05720), [Lassance and Clinchant](https://arxiv.org/html/2207.03834). Code and the usual checkpoint are CC BY-NC-SA 4.0 ([licence file](https://github.com/naver/splade/blob/main/LICENSE)). A BERT model writes a sparse weight for vocabulary terms, and retrieval is a dot product on an inverted index. This is a first-stage retriever. It is not a cross-encoder.
8. **bge-reranker-base, 2023.** [Card](https://huggingface.co/BAAI/bge-reranker-base). MIT, and the card says commercial use is allowed. A 12-layer XLM-RoBERTa cross-encoder. The score is a cross-entropy logit and the authors say it is not bounded to a range.
9. **jina-reranker-v1-tiny-en.** [Card](https://huggingface.co/jinaai/jina-reranker-v1-tiny-en). Apache-2.0. A 4-layer, 33.0M distilled cross-encoder with a long context (8,192 tokens) and a custom JinaBERT body. An int8 ONNX file of 33.4 MB is in the repo ([ONNX tree](https://huggingface.co/jinaai/jina-reranker-v1-tiny-en/tree/main/onnx)). `jina-reranker-v2-base-multilingual` is CC-BY-NC-4.0 ([service README](https://github.com/rahulnitb/bge-reranker-api)).

None of these models score empathy, local cohesion, or persona. Wiring one of them up as a replacement for the whole XiaoIce feature list would be a guess. I don't know of a CPU model trained on those four features together.

## Recommendation

**Now.** Do not add a neural reranker. The live rule already abstains: no covering card, or two cards of equal length, speaks `I don't know.` The spoken line is the card's stored gist, so the source stays the card id. There is no labelled set to fit a threshold, and a public MS MARCO logit is not that threshold. The 8.6 example becomes 0.9998 under a sigmoid, which would almost never abstain.

**Later.** If a frozen set of turns exists, each marked with the right card id or with "no card", then the first neural pick is TinyBERT-L2 over the retrieval thread's four hits. It is Apache-2.0, plain BERT, 4.4M, and it is the only cross-encoder here with a published CPU query time in the tens of milliseconds. Fit one temperature on its logits ([Guo et al., 2017](https://proceedings.mlr.press/v70/guo17a.html)). Speak the winning card's gist only when the calibrated score clears the cut fit on that set and the gap to the second card is wide enough. Otherwise say `I don't know.` If those same turns show TinyBERT missing paraphrases that MiniLM-L6 catches, step up to MiniLM-L6 and accept the 97 ms class of cost from the PALDYN box until a laptop run says otherwise. Quantise only after the cut is fit on the quantised scores: int8 MiniLM moved logits by up to 0.74 in the tiebreak check.

ColBERT-small is the later alternative if the candidate list grows well past four and the card vectors can be built offline. At 1,506 cards the cross-encoder on four hits is the smaller machine. SPLADE weights stay out because of the non-commercial licence. monoT5 stays out until a card states a licence and a laptop time exists. `fastembed` and `candding` stay dev-oracle benches while `ort` and `candle` are locked.

**What would change this.** A laptop run, the merge gate, where TinyBERT-L2 or MiniLM-L6 scores four short gists inside the ranking budget, and the abstain curve on a frozen labelled set beats the covering rule. Or a count, from the real pack, that equal-length ties are dropping a true card often enough to be worth a scorer. I don't know that count. A new owner exception for `ort` would make `fastembed` the shortest path to a bench. This note does not ask for that exception.
